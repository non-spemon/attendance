# 勤怠管理システム（Attendance Management App）　”Kintan”
## 概要
スタッフの利便性と管理者の視認性に特化した、シンプルで直感的な勤怠管理アプリケーションです。

**開発背景（プロダクトへの想い）**

前職の医療現場では、勤務管理がアナログな手法や古い慣習で行われており、管理者自身にとってもスタッフの勤務状況が視覚化されていないという課題がありました。<br>
「現場のスタッフは迷わずワンタップで記録でき、管理者は全スタッフの状況を一目で把握・修正できる」状態を目指し、実務での使いやすさを最優先に設計・開発しました。<br>
今回はその例を使用して、CRUD処理やデータ管理を学ぶためにこのアプリを作りました。<br>

**主な機能**　<br>
一般ユーザーができること：<br>
ログイン、ログアウト。出勤、退勤打刻ボタンのクリック（タップ）<br><br>
管理者（admin）ができること:<br>
ログイン、ログアウト。<br>
ユーザー打刻一覧表示、打刻内容編集・削除<br>
スタッフ新規登録、削除<br>  

**使用技術**　　

PHP 8.x / MySQL / JavaScript / CSS (Flexbox) / XAMPP / GitHub Actions (CI/CD) / エックスサーバ<br>

**こだわった点**　

### SQLによるデータ操作とDRY原則の徹底:
CRUD機能を網羅し、PDOを用いた安全なデータベース操作を実装。<br>
コードの重複を避けるため、共通処理をfunction.phpに集約し、保守性の高いコーディングを意識しました。<br>

### 実用的なUI/UX:
現場での利用を想定し、レスポンシブデザインを採用。<br>
どのデバイスからでも直感的に打刻できるレイアウトを目指しました。<br>
また、index.phpへのアクセスで即座にログイン画面へ誘導するなど、ユーザーの導線も改善しました。<br>

### 苦労したこと:
## 1.開発環境と本番環境の動的な切り替え
工夫した点: SetEnv（環境変数）を用いた接続情報の自動分岐<br>
ローカル環境（MAMP等）と本番環境（エックスサーバー）で、データベースの接続情報を手動で書き換える手間とミスを減らすため、<br>
.htaccess を活用した切り替え機能を実装しました。サーバー固有の設定に苦戦しましたが、一貫したデプロイフローを構築できたことで、開発効率と安全性が向上しました。<br>

## 2.セキュリティを重視したデータ設計
工夫した点: プリペアドステートメントによるSQLインジェクション対策<br>
外部からの不正な入力を防ぐため、PDOのプリペアドステートメントを徹底しました。<br>
単に「動く」コードではなく、ユーザーのデータを守るというエンジニアとしての責任を意識し、セキュリティ面でも堅牢な設計を目指しました。<br>

### 制作を通じて得た「エンジニアとしての視点」
これまではサービスを利用する「ユーザー」でしたが、開発者側に立つことで「この機能は本当に使いやすいか」「もし自分が管理者なら、どんな操作ミスをしそうか」といった一歩踏み込んだ視点を持つようになりました。<br><br>

具体例: 管理者画面での誤削除を防ぐための確認アラート（onsubmit）の実装や、誰が操作しても迷わないUI設計など、ユーザー目線を常に意識して試行錯誤を繰り返しました。<br>


**今後追加したい機能**

### データエクスポート機能:
